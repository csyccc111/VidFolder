# v0.4 发布质量加固 Prompt

规划与提示词：OpenAI Codex（GPT-5），2026-08-10。

## 背景

你是一名资深 Electron + React + TypeScript 桌面应用工程师。请在现有 Vid Folder Browser 项目上完成 v0.4 增量开发和发布前质量加固。

Vid Folder Browser 是一个轻量级本地视频文件浏览器，核心用途是通过文件夹、封面和基础元信息快速找到视频。它不是播放器，也不是复杂素材管理器。

重要规则：

- 必须先阅读 `PROJECT_MEMORY.md`、`PROMPT_VERSIONING.md`、`README.md` 和现有实现。
- 不要从零重建项目，不要重复实现 v0.1-v0.3 已有功能。
- 沿用现有 Electron 主进程、preload IPC、React 状态和 JSON 缓存方案。
- 先验证，再修复；性能优化必须有测量结果支持。
- 不修改与本版本目标无关的代码。

## 当前已实现功能

- 选择并记住本地文件夹，递归扫描常见视频格式。
- 增量展示扫描结果。
- 使用 `ffprobe` 获取时长和分辨率。
- 使用 `ffmpeg` 生成并缓存视频封面。
- 按路径、大小和修改时间组成缓存 key。
- 网格与列表视图、搜索、排序、目录筛选、格式/时长/画面筛选。
- 视图模式、排序方式、排序方向和缩略图大小持久化。
- 右键打开所在目录、默认播放器打开、复制路径、重新生成封面。
- 详情面板、状态栏、`ffmpeg` / `ffprobe` 可用性检测。
- 缺少依赖时应用仍可打开、扫描并展示已有缓存。
- v0.3.0 已完成 GitHub Release 发布闭环。

## 本版本目标

将项目从“功能完备”推进到“发布质量可验证”：

- 错误对用户可理解，对开发者可诊断。
- 元信息与封面处理互不错误连带。
- 缓存失效和损坏缓存行为明确、稳定。
- 对 500、2000、5000+ 视频规模有可复现的性能结论。
- 发布前检查和 Release 流程可以重复执行。

## 已确认的现状风险

实施前需以实际代码再次确认以下风险，不要仅根据本 Prompt 猜测修改：

1. 子进程错误可能以英文技术信息直接进入 `VideoItem.error` 并显示在详情面板。
2. 元信息探测与封面生成位于同一处理链中；`ffprobe` 失败时可能阻断仍可执行的封面生成，并把两个状态一起标为失败。
3. 目录遍历对 `readdir` 异常静默返回；根目录无权限时可能被误报为“扫描完成/没有视频”。
4. 缓存命中只依赖缓存记录和 key；缩略图文件缺失、为空或损坏时可能仍被视为 ready。
5. 每处理一个视频就重写完整元信息 JSON、逐项发送 IPC、前端全量数组更新和渲染，可能在大目录下形成瓶颈。
6. 当前构建产物文件名与线上 Release 资产命名规则不一致。

## 本版本只做

### 1. 错误模型与用户提示统一

- 为可预期错误定义稳定分类，至少覆盖：
  - `dependency_missing`：缺少 `ffmpeg` 或 `ffprobe`。
  - `directory_unreadable`：根目录或子目录不可读取。
  - `file_unreadable`：视频不存在、被占用或无读取权限。
  - `probe_failed`：元信息读取失败或返回无效内容。
  - `thumbnail_failed`：封面生成失败或超时。
  - `cache_invalid`：缓存文件缺失、为空或不可读取。
  - `unknown`：无法可靠归类的异常。
- 用户可见信息使用简洁中文，说明“发生了什么”和“受影响的能力”。
- 原始错误、stderr、命令退出信息作为技术详情保留，但默认不直接铺在界面上。
- 不在技术详情中记录或展示无关环境变量、凭据等敏感信息。
- 扫描整体错误、单个文件错误、依赖缺失提示应有不同展示层级，避免重复弹出和提示轰炸。
- 同一文件可分别表达元信息失败和封面失败，不能只用一个含义模糊的总错误覆盖全部状态。

### 2. 元信息与封面任务解耦

- `ffprobe` 失败时，如果 `ffmpeg` 可用，仍应尝试生成封面。
- `ffmpeg` 失败时，已成功读取的时长和分辨率仍应保留。
- 两个阶段分别更新状态、错误和进度计数。
- “重新生成封面”只重试必要阶段；不要无条件破坏仍有效的元信息。
- 缺少某个依赖时，仅对应能力失败，另一能力继续工作。
- 旧缓存数据应兼容读取；如需扩展缓存结构，提供轻量兼容处理，不引入数据库迁移。

### 3. 扫描错误可见性

- 根目录不可读必须使扫描进入明确的错误状态，不能显示“扫描完成”或“没有视频”。
- 子目录不可读时跳过该目录并继续扫描，同时累计警告数量或形成可查看的摘要。
- 单个文件在扫描期间消失或读取失败时继续处理其他文件。
- 取消扫描、目录为空、目录不可读必须是三个可区分状态。
- 中文路径、空格路径、长文件名和常见特殊字符不得退化。

### 4. 缓存失效与自愈

- 验证并记录以下场景：
  - 文件大小变化。
  - 文件大小相同但 mtime 变化。
  - 路径、大小、mtime 均不变但内容变化。
  - 原视频已删除但 metadata-cache 或缩略图仍残留。
  - 缩略图文件缺失、零字节、截断或无法解码。
  - metadata-cache JSON 损坏。
- 对路径、大小、mtime 均不变但内容变化，默认接受为当前 key 策略的已知限制，不新增全文件哈希。
- 缩略图缺失或明显无效时，将其降级为待生成并自动重试，不得导致应用崩溃。
- metadata-cache JSON 损坏时应用仍可启动，并安全回退为空缓存；不得覆盖用户视频文件。
- 明确孤儿缓存策略。缓存跨多个已浏览文件夹共用，不能因为当前扫描未出现某条记录就直接删除它。元信息清理只处理当前扫描根目录范围内已确认不存在的源文件；缩略图只清理不再被任何有效缓存记录引用的文件。
- 所有清理只能操作应用自己的缓存目录和缓存索引。执行前规范化并校验目标路径，禁止跟随范围外路径或操作用户视频文件。
- 若清理策略可能显著增加启动/扫描耗时，可先记录数量并延后删除，但必须在测试报告中说明决定。

### 5. 大目录性能基准与条件式优化

建立可重复的三档测试集：约 500、2000、5000+ 个真实可探测视频。测试集应包含多层目录、中文路径、空格和常见特殊字符，并记录机器配置、视频总数、总大小、目录层级和 `ffmpeg` / `ffprobe` 版本。如果仓库内没有合适测试素材，先向用户索要少量可用于复制构造数据集的代表性视频，不要擅自下载来源不明的媒体。

基准测试使用隔离的测试配置/缓存目录，不读取、清空或污染用户日常使用的缓存。以接近发布环境的打包构建为主要测试对象；每个关键场景至少重复 3 次并记录中位数，同时保留最大值以观察抖动。

每档至少执行：

- 冷缓存：无元信息和缩略图缓存。
- 热缓存：缓存完整有效。
- 混合缓存：部分命中、部分失效、部分损坏。
- 网格与列表的搜索、筛选、排序和滚动操作。

分别记录：

- 首个视频出现时间。
- 文件发现完成时间。
- 元信息完成时间和吞吐量。
- 封面完成时间和吞吐量。
- 扫描期间 UI 可交互性与明显长任务。
- 空闲、扫描峰值和完成后的内存占用。
- 热缓存二次扫描耗时。
- 失败数量及分类。

性能基线采用“必须记录、条件触发修复”的方式：

- 5000+ 热缓存扫描过程中，窗口不能长期无响应或崩溃。
- 首批结果应增量出现，不能等待全部扫描后一次性展示。
- 搜索、筛选、排序操作不应出现持续数秒的冻结。
- 内存不能在扫描结束后持续无界增长。
- 手工判定“流畅/卡顿”之外，应保留至少一种可复核证据，例如操作录屏、DevTools Performance 记录或按固定间隔采样的进程内存数据。
- 测试若证明瓶颈来自全量 JSON 高频写入、IPC 频率或全量列表渲染，只优化被证实的环节，并记录优化前后对比。

允许的针对性优化包括：

- 元信息缓存写入合并、节流和结束时 flush，同时保证异常退出时损失范围可接受。
- IPC 进度节流或条目批量发送，同时保持首批结果及时出现。
- React 状态更新从线性查找改为更适合大量条目的结构。
- 仅在 5000+ 实测确认渲染为主要瓶颈时，引入轻量虚拟化；避免无依据增加依赖。

### 6. 发布检查与文档

  - 网格/列表、设置恢复、搜索、筛选、排序。
  - 右键四项操作。
  - `ffmpeg` 缺失、`ffprobe` 缺失、两者均缺失。
  - 损坏视频、目录无权限、缓存损坏。
  - 中文、空格和特殊字符路径。

## 本版本不做

- 不新增播放器、悬停多帧预览或封面候选选择。
- 不新增标签、收藏、最近文件夹或 CSV 导出。
- 不做删除、移动、重命名和批量文件管理。
- 不内置或自动下载 `ffmpeg` / `ffprobe`。
- 不引入数据库、后台服务、登录、云同步。
- 不为了潜在性能问题进行大规模架构重写。
- 不使用全文件内容哈希替代当前缓存 key。
- 不清理应用缓存目录之外的任何文件。

## 验收标准

- 所有常规用户可见错误为简洁中文，不显示裸 stderr 或技术堆栈。
- 技术详情仍可用于诊断，且与用户文案分离。
- `ffprobe` 失败不会阻止可执行的封面生成；`ffmpeg` 失败不会丢失有效元信息。
- 根目录不可读显示扫描错误；子目录不可读时继续扫描并给出警告摘要。
- 取消扫描后显示 `cancelled` 状态并保留取消时已有统计，不误报为扫描完成。
- 缩略图缺失、零字节或明显损坏后能降级并重新生成，应用不崩溃。
- metadata-cache JSON 损坏时应用可启动并回退。
- 缓存五类以上场景均有“预期、实测、结论、是否修复”记录。
- 500、2000、5000+ 三档均有冷/热缓存测试数据、环境说明和瓶颈结论。
- 性能修复如发生，报告包含优化前后对比；如未发生，报告说明现状为何可接受。
- 发布冒烟清单可由不了解实现细节的人独立执行。
- 本地打包资产名称与线上 Release 命名一致。
- README 和发布流程文档与实际命令、产物路径一致。
- `npm run typecheck`、`npm run build`、`npm run dist:zip` 成功。
- v0.1-v0.3 已有浏览功能无回归。
