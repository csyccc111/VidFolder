# v0.9 ffmpeg 依赖解决 Prompt（智能探测 + 按需下载）

规划与提示词：DeepSeek-V4 Flash（agent: opencode），2026-08-23。

## 背景

你是一名资深 Electron + React + TypeScript 桌面应用工程师。请在现有 Vid Folder Browser 项目上进行 v0.9 增量开发。

当前应用依赖本机 PATH 中的 `ffmpeg` / `ffprobe`（缺失时封面、元信息、悬停预览不可用），这是"解压即用"的最大门槛。本版本解决依赖问题，分两阶段：

1. **智能探测**：不依赖 PATH，探测常见安装位置并持久化实际路径。
2. **按需下载**：缺失时引导用户下载 ffmpeg 静态构建到应用数据目录（带 SHA-256 校验与版本记录），下载后自动使用。

重要规则：

- 开始前阅读 `PROJECT_MEMORY.md`、`PROMPT_VERSIONING.md`、README 和当前实现。
- 沿用 v0.4 错误模型与现有依赖检测 IPC；不要重构扫描/缓存/预览链路。
- 下载失败、校验失败、解压失败都必须优雅降级到"现状缺失依赖行为"，绝不阻塞浏览。
- 只支持 Windows x64（本产品当前唯一发布目标）。
- 下载源固定（GitHub Releases 上的 ffmpeg 静态构建），来源与版本策略需在实现前确认并记录理由。
- 中文内容和源码统一使用 UTF-8。

## 本版本目标

- 用户在常见安装场景下（PATH 已配 / 已装未配 PATH / 未装）都能顺利获得可用依赖。
- 探测结果持久化，后续进程启动直接用持久化路径，不依赖 PATH 解析。
- 未安装时应用内引导下载，全程可见进度与失败原因，可重试。
- 下载的 ffmpeg 与系统安装版本共存时优先使用应用内版本（可设置切换）。

## 交互与行为定义

### 1. 智能探测

- 探测顺序（首个可用即停）：
  1. 应用数据目录 `vendor/ffmpeg/`（应用内管理版本，最高优先）。
  2. 设置中用户手动指定的路径（`ffmpegPath` / `ffprobePath` 覆盖）。
  3. 系统 PATH。
  4. 常见安装位置：`C:\ffmpeg\bin`、`C:\Program Files\ffmpeg\bin`、scoop（`%USERPROFILE%\scoop\apps\ffmpeg\current\bin`）、chocolatey（`C:\ProgramData\chocolatey\bin`）、winget（`%LOCALAPPDATA%\Microsoft\WinGet\Packages` 下递归查找 `ffmpeg.exe`）。
- 探测到的绝对路径持久化到设置；每次启动重新验证存在性，失效则重新探测。
- 状态栏/顶部提示从"缺少 ffmpeg"细化为："未检测到 / 使用系统版本 <版本> / 使用应用内版本 <版本>"。
- 提供"重新检测"操作。

### 2. 按需下载

- 触发时机：检测缺失时，状态栏提示旁出现"下载 ffmpeg"按钮（不自动弹窗、不自动下载）。
- 下载源：BtbN/FFmpeg-Builds 的 GitHub Release（`ffmpeg-master-latest-win64-gpl-shared` 或稳定 release 的 essentials 包，实现前确定并记录），固定下载 URL 模板。
- 流程：下载 zip → 校验 SHA-256（与内置清单比对；清单随代码维护）→ 解压到 `vendor/ffmpeg/<版本号>/` → 校验 bin 下存在 ffmpeg.exe / ffprobe.exe → 写版本记录 → 触发重新探测。
- UI：下载进度（百分比 + 速度或已下载/总量，主进程下载、IPC 推送进度）、失败原因（网络/校验/解压）与重试按钮；下载窗口可关闭且不中断浏览。
- 失败回退：任何一步失败都保持"缺失依赖"现状，可随时重试。
- 校验失败时必须删除已下载内容并提示"校验失败，可能被篡改或源变更"，不静默接受。
- 断点续传不做（zip 下载体积可控，重试即可）；下载并发仅允许一个任务。

### 3. 使用与切换

- 执行 ffmpeg/ffprobe 的封装从"PATH 查找"改为"解析后的绝对路径"（无则保持现缺失逻辑）。
- 设置中可查看当前使用的依赖来源与版本；可"恢复到系统版本"（删除或忽略 vendor 版本记录，保留文件以便切回）。

## 本版本只做

1. 探测模块（顺序探测、持久化、失效重探）。
2. 下载管理（下载、SHA-256 校验、解压、版本记录、进度与取消、单任务并发）。
3. 执行层改造（绝对路径使用）。
4. 状态栏细化与下载引导按钮。
5. 下载/校验/解压的失败分类与用户文案（沿用 ErrorCategory）。
6. README 许可声明（ffmpeg 静态构建为 GPL；本项目开源，随附二进制需注明来源与许可证）。
7. 安全：vendor 目录路径规范化校验；解压只允许在应用数据目录内，防 zip-slip（解压时校验相对路径不越界）。

## 本版本不做

- 不把 ffmpeg 打进安装包 zip（体积权衡，后续可再评估）。
- 不自动静默下载（必须用户确认后下载）。
- 不做 ffmpeg 版本自动更新（仅首次按需下载；版本升级由后续版本或手动重下）。
- 不支持 macOS / Linux 的探测与下载。
- 不做多架构（arm64）支持。
- 不改变扫描、缓存、预览、进度记忆等既有行为。

## 实现要求

- 所有 ffmpeg/ffprobe/ffplay 调用统一走一个解析器（resolveBinary），禁止散落 PATH 逻辑。
- 下载使用 Electron 主进程 net/https（不信任渲染进程 URL；下载 URL 由主进程常量生成）。
- 进度推送节流（每 ~100ms 或每 1% 一次），避免 IPC 风暴。
- zip-slip 防护必须实现并单测覆盖。
- SHA-256 清单格式与校验逻辑单测覆盖；校验失败路径有明确行为。
- 解压到 vendor 时若磁盘空间不足给出明确错误。

## 验收标准

- 三场景实测：PATH 已配置 / 已安装未配 PATH（放入常见目录模拟）/ 完全未安装：
  - 前者直接可用并显示系统版本；
  - 中者探测到并可用；
  - 后者引导下载，下载→校验→解压→启用全链路成功，重启后仍有效。
- 下载中断、校验失败、解压失败均有明确文案与重试入口，应用不崩溃、浏览不阻塞。
- 下载成功后悬停预览、封面生成、元信息读取全部可用。
- 恢复系统版本操作生效。
- 恶意 zip（路径穿越条目）被拒绝。
- `npm run typecheck`、`npm run build`、相关单测通过。
