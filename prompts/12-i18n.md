# v0.12 英文界面 Prompt（i18n）

规划与提示词：DeepSeek-V4 Flash（agent: opencode），2026-08-23。

## 背景

你是一名资深 Electron + React + TypeScript 桌面应用工程师。请在现有 Vid Folder Browser 项目上进行 v0.12 增量开发。

当前全部 UI 文案与主进程错误消息为中文硬编码。本版本引入国际化：中/英双语，语言设置（跟随系统 / 手动选择），并将主进程错误从"发送中文 message"改为"发送错误码 + 渲染进程按语言翻译"。

重要规则：

- 开始前阅读 `PROJECT_MEMORY.md`、`PROMPT_VERSIONING.md`、README 和当前实现。
- 这是**文案体系重构**：不允许改动任何业务逻辑、数据格式、缓存结构或 IPC 协议语义（IPC 字段名不变）。
- 所有功能文案必须全部抽取，不允许残留硬编码中文/英文 UI 字符串（错误 detail 等技术字符串可保留原文）。
- 主进程错误模型（v0.4 ErrorCategory / ItemError）中"用户可读中文 message"改为错误码，渲染进程翻译；`detail`（技术信息）保持原样。
- 默认语言跟随系统（Windows 显示语言），可手动覆盖并持久化。
- 中文内容和源码统一使用 UTF-8。

## 当前已实现功能

- v0.1-v0.11 全部能力（含重复检测）。
- 文案分布：渲染进程组件/工具函数（大量中文模板字符串）、主进程错误消息（`ScanError`/`toItemError` 等）、preload 暴露字符串。
- 设置持久化 `settings.json` 已有通用结构。

本版本的重新实现目标：无（纯文案层改造）。

## 本版本目标

- 应用整体可在中文/英文之间切换，无需重启（或实现简单明确：切换后立即生效）。
- 语言设置：跟随系统（默认）/ 简体中文 / English；持久化。
- 主进程只发错误码，所有用户可见文案在渲染进程按当前语言渲染；旧有中文 message 字段迁移为 code + 渲染端字典，兼容旧缓存（v0.3 遗留 error 字符串）展示。

## 交互与行为定义

- 设置入口：工具栏或设置面板新增"语言"下拉（跟随系统 / 中文 / English）。
- 切换即时生效；持久化；重启保持。
- 随系统语言变化：启动时读取一次并应用（运行中系统语言变更可不必实时响应，文档记录取舍）。
- 所有可交互控件（按钮/菜单/提示/状态栏/详情/筛选/预览角标时间文案等）均参与翻译；文件名、路径、时间数字格式不翻译（时间格式可复用现有规则，不引入 locale 数字差异）。

## 本版本只做

1. 引入 i18n 方案：`i18next` + `react-i18next`（渲染进程），主进程不使用 i18n 库（仅维护 code→字段）。
2. 建立字典结构：`src/i18n/zh.json`、`src/i18n/en.json`；key 按模块组织（scan / error / contextmenu / detail / status / settings / update / duplicate / preview 等）。
3. 全量抽取渲染进程文案（组件 + lib 格式化函数中的可读文案）。
4. 主进程错误改造：ErrorCategory + 新增稳定错误码（如 `"err.ffmpeg_missing"`）；`toItemError` 输出 `{ code, detail }`（message 可为空或保留英文兜底）；渲染端按 code 翻译；v0.3 旧缓存 error 字符串 → 映射为通用码或原样展示（不崩溃）。
5. 语言设置（跟随系统检测：`app.getLocale()` 或系统 locale）与持久化、切换即时生效。
6. 单测：字典 key 完整性（zh/en key 集合一致）、错误码覆盖（所有主进程抛出的 code 均有字典项）。
7. README 更新（语言支持说明）。

## 本版本不做

- 不做其他语言（仅中/英）。
- 不做 RTL、数字/日期 locale 化。
- 不改变 IPC 协议字段名与数据结构（只改 message 字段的语义为 code）。
- 不重命名或重构组件、不整理组件边界。
- 不修改业务逻辑与缓存格式（错误码迁移除外）。
- 不引入第三方 i18n 编辑器/翻译服务。

## 涉及模块建议

- `src/i18n/`：字典、初始化、语言 hook。
- `src/shared.ts`：错误码类型（`ErrorCode` union）+ ItemError 结构调整。
- `electron/main.ts`：错误分类处输出 code。
- 全部组件：文案替换为 `t()`。
- `electron/main.ts` 系统语言检测；`settings.json` 新增 `language` 字段。
- `scripts/check-i18n.cjs`（可选）：CI/本地校验字典 key 一致性。

## 实现要求

- key 命名稳定：语义化 + 模块前缀，变更需更新字典；单测保证 zh/en 一致。
- 带参数文案（如"上次看到 {time}"）使用 i18n 插值，禁止字符串拼接翻译。
- 主进程保留一个"兜底语言"（英文）用于错误码解析失败时展示 detail。
- 默认语言：`app.getLocale()` 前缀匹配 `zh` → 中文，否则英文；手动选择后持久化覆盖。
- 性能：切换语言不重新加载窗口（React 状态驱动）；字典按需挂载（懒加载非必需，项目小，可全量）。
- 旧缓存中 v0.3 的 error 字符串：渲染端做一次映射表兼容展示，不抛错。

## 验收标准

- 中文与英文界面全量切换：扫描、筛选、排序、右键、详情、预览角标、进度记忆、更新检查、重复检测、依赖下载（v0.9）所有可见文案均翻译且无硬编码残留（代码扫描确认）。
- 主进程错误按当前语言正确显示；错误码无字典缺失（单测断言）。
- 语言设置持久化；跟随系统在 zh 与 en 系统下分别生效。
- 切换语言不丢扫描结果、不重置 UI 状态、不重启。
- 旧缓存含 v0.3 error 字符串时不崩溃并合理展示。
- 中英文下中文文件名/路径/特殊字符均正常。
- `npm run typecheck`、`npm run build`、相关单测通过。
