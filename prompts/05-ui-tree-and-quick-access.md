# v0.5 界面体系、文件夹树与快速访问 Prompt

规划与提示词：OpenAI Codex（GPT-5），2026-08-13。

## 背景

你是一名资深 Electron + React + TypeScript 桌面应用工程师。请在现有 Vid Folder Browser 项目上进行 v0.5 增量开发。

Vid Folder Browser 是轻量级本地视频文件浏览器，核心价值是帮助用户通过文件夹结构、封面和元信息快速找到视频。它不是视频播放器，也不是复杂素材管理器。

本版本进行一次有边界的前端体验重构：接入 shadcn/ui，建立统一组件体系，把现有扁平目录列表升级为文件夹树，并加入最近/常用文件夹和基础键盘操作。

实施时以官方资料为准：

- 文档：<https://ui.shadcn.com/docs>
- 安装说明：<https://ui.shadcn.com/docs/installation>
- 官方仓库：<https://github.com/shadcn-ui/ui>

重要规则：

- 开始前阅读 `PROJECT_MEMORY.md`、`PROMPT_VERSIONING.md`、`README.md`、`prompts/04-release-hardening.md` 和当前源码。
- 这是增量重构，不要从零创建新应用，不要重写 Electron 主进程的扫描、缓存和视频处理逻辑。
- 在改造前记录现有主要工作流，重构后逐项回归。
- 使用官方 shadcn/ui 文档中适用于“已有 Vite 项目”的接入方式。
- shadcn/ui 是进入仓库并由项目维护的组件源码。只加入本项目实际使用的组件，不克隆整个 `shadcn-ui/ui` 仓库，也不复制示例应用。
- 使用同一种底层组件体系并保持一致，优先采用官方稳定的 Radix 方案；不要混用 Radix、Base UI 和其他同类组件库。
- 新增依赖前说明用途，避免引入完整 UI 套件或重量级文件树库。
- 中文内容和源码统一使用 UTF-8。

## 当前已实现功能

当前基线为 v0.4，后续开发不得把这些功能当作从零任务：

- 选择并记住本地文件夹，递归扫描常见视频格式。
- 增量显示扫描结果，支持刷新与取消。
- 使用 `ffprobe` 获取时长和分辨率。
- 使用 `ffmpeg` 生成封面，缓存元信息与缩略图。
- 网格/列表视图、文件名搜索、排序、目录筛选、格式/时长/画面筛选。
- 视图模式、排序字段、排序方向和缩略图大小持久化。
- 左侧目录显示累计视频数，但目前是扁平列表。
- 右键打开所在目录、默认播放器打开、复制路径、重新生成封面。
- 详情面板、状态栏、依赖检测、中文错误模型、扫描警告。
- 元信息与封面任务已解耦，损坏缓存具备基础自愈。
- 构建资产命名和发布文档已经统一。

注意：v0.4 的大目录性能基准、缓存验证、完整冒烟和发布闭环如果尚未执行，先记录为前置质量债务。v0.5 不得删除或规避这些验证要求。

## 本版本目标

- 建立一致、可维护、无障碍基础更好的桌面工具 UI 组件体系。
- 让用户通过真正的层级文件夹树理解并筛选当前视频目录。
- 让用户快速进入最近打开或固定的常用文件夹。
- 提升键盘操作、布局适应和高频浏览效率。
- 保持 v0.1-v0.4 所有业务能力和数据安全边界不变。

## 本版本只做

### 1. shadcn/ui 基础接入

- 按官方“Existing Vite Project”方式接入 shadcn/ui 所需基础设施，包括必要的 Tailwind 配置、路径别名、`components.json`、样式入口和工具函数。
- 使用 Lucide 图标，不手写可由现成图标表达的 SVG。
- 仅添加本版本需要的组件，建议范围：
  - `Button`
  - `ToggleGroup` 或 `Toggle`
  - `Select`
  - `DropdownMenu` / `ContextMenu`
  - `Tooltip`
  - `Sidebar`
  - `ScrollArea`
  - `Collapsible`
  - `Separator`
  - `Alert`
  - `Progress`
  - `Skeleton`
  - `Popover`
  - `Command`
  - `Sheet`
- 不要求机械替换每一个 HTML 标签。优先迁移工具栏、筛选控件、侧栏、菜单、提示和布局基础组件。
- 保留项目自己的视频卡片、视频列表行、文件夹树节点等领域组件，不强行套成通用 Card。
- 主题保持紧凑、克制、工作导向。卡片圆角不超过 8px，避免大面积渐变、装饰性背景和营销页面风格。
- 至少提供完整暗色主题；可以预留明亮主题变量，但本版本不要求主题切换器。

### 2. 前端结构整理

- 将当前承担大量职责的 `App.tsx` 按实际边界拆分，建议包含：
  - 应用壳与布局。
  - 顶部工具栏和筛选区。
  - 快速访问侧栏。
  - 文件夹树及递归节点。
  - 视频网格、视频卡片。
  - 视频列表和可排序表头。
  - 视频详情面板。
  - 状态栏、扫描错误与警告。
- 将纯格式化、路径比较、筛选和排序函数移入明确的工具模块，并为高风险纯函数增加聚焦测试。
- 不为了“组件化”制造大量只有一层转发的文件。拆分应减少状态耦合或提高可测试性。
- 业务状态保持单一来源，不在多个组件复制扫描结果、选中项或筛选状态。
- 不引入 Redux、数据库或新的全局状态框架；现有 React 状态和必要的 Context 足以满足本版时优先沿用。

### 3. 层级文件夹树

- 使用当前扫描结果中的 `VideoItem.directory` 构造树，不额外遍历和展示与视频无关的空目录。
- 树应包含扫描根节点、包含视频的文件夹及其必要祖先。
- 每个节点至少包含：稳定 id、绝对路径、显示名称、相对路径、直接视频数、包含全部后代的累计视频数、子节点。
- Windows 路径比较应大小写不敏感，同时保留原始路径用于显示和系统操作。
- 树节点支持展开/折叠；点击节点筛选该目录及全部子目录的视频。
- 展开按钮和筛选选择是两个清晰动作，点击箭头不能意外切换筛选。
- 当前选中节点高亮，并自动确保其祖先展开和节点可见。
- 根节点承担“全部视频”语义并显示总数。
- 默认展开根节点；对于只有一条连续分支的浅层目录，可保持自然展开，但不要首次加载时展开所有大型树。
- 提供全部折叠操作；是否提供全部展开应考虑大型目录，若提供必须有限制或提示。
- 记住每个根文件夹对应的展开节点集合，设置写入应节流，并设置合理上限，防止 `settings.json` 无界增长。
- 文件夹名称过长时截断，Tooltip 显示完整路径。
- 文件夹树提供名称过滤。过滤时显示匹配节点及其祖先；清除搜索后恢复此前展开状态。
- 目录节点右键菜单至少支持“在资源管理器中打开”。不得加入删除、移动、重命名。
- 键盘和无障碍行为至少覆盖：上下移动可见节点、左右展开/折叠或移动层级、Enter 选择、可见焦点、正确的 tree/treeitem 语义或等价可访问实现。
- 大型树只渲染当前展开分支。若 v0.4/v0.5 实测仍存在明显瓶颈，再考虑虚拟化，不预先引入重量级树组件。

### 4. 最近文件夹与常用文件夹

- 保存最近成功打开的文件夹，默认最多 10 条，按最近使用时间降序排列并按规范化路径去重。
- 用户可以固定/取消固定文件夹。固定项不因最近列表上限被淘汰。
- 用户可以从最近记录中移除条目；移除记录不得删除真实文件夹或应用缓存。
- 点击记录后先验证路径是否存在且为目录，再开始扫描。
- 无效路径显示低干扰状态，允许移除或重新定位，不因单条失效阻止应用启动。
- 快速访问区至少区分“已固定”和“最近使用”，空状态简洁。
- 当前根文件夹切换成功后更新最近记录；对话框取消、扫描启动失败不应错误写入成功历史。
- 数据继续存入 `settings.json`。建议使用带时间戳的结构化记录，不新增数据库。
- 对设置中的旧数据、重复路径、格式异常和超出上限数据做兼容清理。
- 可支持从 Windows 资源管理器向应用窗口拖入一个文件夹并打开：
  - 只接受单个目录。
  - 拖入普通文件或多个目标时给出清晰提示。
  - 不读取网络内容，不改变拖入目录中的任何文件。

### 5. 高频浏览与键盘操作

- 双击视频卡片或列表行时，使用系统默认播放器打开。
- 在视频区域支持方向键移动当前选择，行为应结合网格列数和列表顺序合理处理。
- `Enter` 打开当前视频，`Ctrl+C` 复制当前视频完整路径。
- 键盘操作在输入框、Select、Command、菜单等编辑/弹出控件中不得误触发。
- 选择变化后确保目标在可视区域内，详情面板同步更新。
- 提供回到当前选中视频所在文件夹节点的操作，复用文件夹树选择逻辑。
- 使用 Tooltip 说明不熟悉的图标按钮；不要在主界面堆放快捷键教学文字。

### 6. 工作区布局与视觉规范

- 建议布局：顶部紧凑工具栏；左侧快速访问和文件夹树；中央网格/列表；右侧详情；底部精简状态栏。
- 左侧栏可折叠；若实现可调整宽度，宽度应有最小/最大值并持久化，拖拽不能造成主区域不可用。
- 右侧详情面板可收起，并记住开关状态。
- 窄窗口下，详情面板使用 Sheet 或等价覆盖层，不得与主内容重叠失控。
- 筛选条件可放入 Popover 或紧凑筛选区，并显示当前有效筛选数量；清除筛选保持易发现。
- 网格卡片和列表行保持稳定尺寸，加载、错误、选中、悬停状态不得引发布局跳动。
- 用户错误、扫描警告和依赖缺失继续遵循 v0.4 中文文案与技术详情分离规则。
- 保证中文文本、长路径和长文件名不溢出控件。

## 建议数据结构

以下仅表达语义，可根据现有代码调整命名：

```ts
type FolderTreeNode = {
  id: string;
  path: string;
  name: string;
  relativePath: string;
  directVideoCount: number;
  totalVideoCount: number;
  children: FolderTreeNode[];
};

type FolderHistoryEntry = {
  path: string;
  lastOpenedAt: number;
  pinned: boolean;
};

type AppSettings = {
  // 保留现有字段
  recentFolders?: FolderHistoryEntry[];
  expandedFoldersByRoot?: Record<string, string[]>;
  sidebarOpen?: boolean;
  sidebarWidth?: number;
  detailPaneOpen?: boolean;
};
```

持久化路径前应考虑键名长度和 Windows 大小写规则。展开状态可以使用相对路径或稳定 hash，避免绝对路径重复造成文件膨胀。

## 本版本不做

- 不做悬停多帧预览；该功能属于 v0.6。
- 不做多候选封面选择或自定义时间点封面。
- 不做内置播放器、播放控制、音频播放。
- 不做删除、移动、重命名、批量文件操作。
- 不做标签、视频收藏、重复文件检测、CSV/JSON 导出。
- 不做文件夹实时监控、多根目录聚合、云同步、登录。
- 不内置或自动下载 `ffmpeg` / `ffprobe`。
- 不扫描完整磁盘，不展示没有视频且不属于祖先链的目录。
- 不克隆或依赖 shadcn/ui 的完整源码仓库，不把官方示例站整体搬入项目。

## 涉及模块建议

- `components.json`、Tailwind/Vite/TypeScript 配置：shadcn/ui 基础接入。
- `src/components/ui/`：由 shadcn CLI 加入并由项目维护的基础组件。
- `src/components/`：文件树、快速访问、工具栏、视频视图、详情和状态组件。
- `src/lib/`：路径规范化、树构造、筛选排序、设置兼容工具。
- `src/App.tsx`：收敛为应用状态编排与顶层布局。
- `src/shared.ts`：历史记录、设置和必要 IPC 类型。
- `electron/main.ts`、`electron/preload.cts`：文件夹验证、目录右键操作、拖入目录验证等最小 IPC 增量。
- `README.md`、`PROJECT_MEMORY.md`：更新组件体系、功能和版本记录。

## 验收标准

- 项目通过官方支持方式接入 shadcn/ui，所用组件源码位于项目内且可维护。
- 没有克隆整个 shadcn-ui/ui 仓库，没有引入无关组件和示例页面。
- UI 保持轻量桌面文件工具风格，布局在允许的最小窗口和常用桌面尺寸下无重叠、溢出或不可达操作。
- 左侧显示真正的层级文件夹树，父子关系、累计数量和筛选结果正确。
- 展开/折叠与选择动作互不误触；选中节点的祖先自动展开。
- 文件夹树搜索、全部折叠、目录右键打开和键盘导航正常。
- 重启后能恢复合理范围内的树展开状态、侧栏状态和详情栏状态。
- 最近文件夹按时间排序、路径去重且不超过上限；固定项稳定保留。
- 无效历史路径不会导致崩溃，移除历史不会删除真实文件。
- 单个文件夹拖入可打开，错误拖入有明确提示。
- 双击、方向键、Enter、Ctrl+C 在非编辑状态下按预期工作。
- 所有 v0.1-v0.4 功能仍可用，错误分类和缓存安全边界未退化。
- `npm run typecheck` 和 `npm run build` 通过。
- 对树构造、路径归一化、最近记录去重/淘汰等纯逻辑有聚焦测试。

## 回归检查

- 启动恢复上次目录、视图、排序和缩略图大小。
- 选择、刷新、取消扫描正常，扫描错误和警告正确显示。
- 网格/列表切换、搜索、筛选、排序和清除筛选正常。
- 目录树筛选结果等同于原有“目录及全部子目录”语义。
- 列表表头排序、视频选择和详情同步正常。
- 右键四项功能正常，中文、空格、长路径正常。
- 缺少 `ffmpeg` 或 `ffprobe` 时应用仍可浏览文件和已有缓存。
- 损坏缓存自愈和跨文件夹缓存清理边界不受影响。
- Windows x64 构建可启动。
