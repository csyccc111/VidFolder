## 本版本目标

- 列表视图中也能通过悬停快速预览视频内容，交互与网格一致但适配行布局。
- 记住每个视频的播放进度与"是否看完"，以角标形式辅助浏览决策。
- 在打开有进度的视频时，尽量从上次位置继续（仅当环境允许），否则明确告知。
- 进度记录不得拖慢扫描、打开、排序或窗口交互；存储写入节流。
- 列表预览不得破坏 v0.6 网格预览的既有行为与性能特征。

## 交互定义

### 1. 列表视图悬停预览

- 仅列表视图启用本交互；网格视图维持 v0.6 行为不变。
- 鼠标悬停列表行约 400ms 后，在该行下方（或行内缩略图上方）浮出**横向胶片预览条**：8 帧一排，帧间分隔，底部显示当前帧时间。
- 鼠标在预览条内水平移动切换帧并高亮当前帧；角标时间实时更新（复用现有时长格式化）。
- 鼠标移出预览条与所属行约 200ms 后预览条消失，恢复行原状。
- 列表滚动、键盘导航（方向键/Enter）、排序变化、筛选变化、切换文件夹、取消扫描时，预览条立即关闭并取消未开始请求。
- 同一时刻全局只允许一个可见预览会话（网格与列表共用同一套会话与 requestId 体系，天然互斥）。
- 预览帧尺寸按行缩略图区域适配（小图级别，如 `scale=240:-1` 量级），不放大为网格封面尺寸。
- 预览条为浮层（绝对定位），不得推动行布局、遮挡选中高亮或干扰双击/右键。
- 缺少 ffmpeg 时与网格一致：开关禁用并 Tooltip 说明。

### 2. 播放进度记忆

- 数据来源：打开视频时开始计时并在应用内记录；或基于用户操作显式标记。进度记录包含：视频路径、位置（秒）、时长（复用 ffprobe 结果）、是否看完、更新时间。
- 双击打开视频时：
  - 若存在"未看完"记录且系统检测到 `ffplay`（随 ffmpeg/ffprobe 一并提供）：询问一次"从上次位置（mm:ss）继续？"，确认后用 `ffplay -ss <位置>` 打开，拒绝则从头打开并视为看完。
  - 若无 `ffplay`：按现状用系统默认播放器打开，进度记录保留，不弹窗打扰（可在角标 Tooltip 中说明"上次看到 mm:ss"）。
- 角标展示：网格封面与列表行缩略图角标显示细进度条与百分比（未看完时）；看完的视频不再显示角标。
- 右键菜单新增："标记为已看完"、"重置播放进度"。
- 存储：独立 `progress.json`（与 settings.json 分离），路径规范化去重，写入节流（至少 500ms 合并或卸载时落盘）；源文件 size/mtime 变化时对应进度记录失效并清理。
- 记录条目上限（如 2000 条，超限按最旧淘汰），避免大目录无限膨胀。

## 本版本只做

1. 列表视图悬停预览：行 hover 状态机（复用网格 400ms 触发逻辑）、胶片预览条浮层组件、帧映射与高亮、与网格共享会话互斥、滚动/键盘时关闭。
2. 播放进度记录模型、存储、节流写入与失效清理。
3. 角标渲染（进度条 + 百分比 + 未看完状态）。
4. `ffplay -ss` 继续播放路径与无 ffplay 时的降级提示。
5. 右键菜单两项新命令与详情面板显示"上次看到 mm:ss / 继续播放"。
6. 列表预览性能记录（连续悬停 50 行、快速上下滚动、缓存命中切换）。

## 本版本不做

- 不做内置播放器、视频流播放、音频、时间轴拖动、倍速或逐帧编辑。
- 不做"保存预览帧为主封面"、多候选封面选择。
- 不做列表批量预生成预览帧。
- 不自动替换系统默认播放器，不修改默认打开行为。
- 不引入数据库；进度记录用 JSON 文件。
- 不内置或自动下载 ffmpeg（属于 v0.9）。
- 不重构 v0.5/v0.6 的 UI、树、快速访问或预览缓存架构。

## 涉及模块建议

- `src/shared.ts`：进度记录类型、列表预览请求复用现有 PreviewRequest 类型。
- `electron/main.ts` 或独立模块：ffplay 检测与 `-ss` 启动、进度读写与失效清理（主进程预览链路尽量不动）。
- `electron/preload.cts`：进度相关最小 IPC（读取/写入/清除/标记）。
- 列表行组件：hover 状态机、胶片预览条浮层。
- 视频卡片/行组件：进度角标。
- 右键菜单与详情面板：新命令与进度展示。
- `README.md` 与 `docs/`：列表预览与进度记忆说明。

## 实现要求

- ffplay 检测沿用现有 ffmpeg/ffprobe 探测结果扩展（`which`/`where` 同级探测），不重复 spawn。
- 列表滚动性能不能因预览层退化：滚动中不创建预览任务，只有停留 400ms 才触发。
- 浮层渲染用现有 shadcn/ui 风格；所有时间展示复用现有格式化规则。
- 进度写入合并节流；应用退出（before-quit）时最后一次落盘。
- 陈旧结果隔离复用 v0.6 requestId 机制，列表与网格不得互相覆盖。
- 不做任何文件系统写操作到用户视频目录。

## 验收标准

- 列表行悬停约 400ms 出现胶片预览条，水平移动稳定切换帧并高亮。
- 滚动、键盘操作、排序、筛选变化时预览条立即关闭且无陈旧帧残留。
- 网格与列表预览互斥：网格预览中移到列表行不会出现两个预览会话。
- 双击打开未看完视频：有 ffplay 时给出继续选项并可跳转；无 ffplay 时正常打开且不打扰。
- 角标进度条与百分比正确，看完后消失；"标记为已看完 / 重置进度"生效。
- 源文件 size/mtime 变化后旧进度失效并清理。
- 连续悬停 50 行与快速滚动压力测试有记录，无内存/CPU 异常增长。
- 未启用预览时列表滚动性能与 v0.6 无明显差异。
- `npm run typecheck`、`npm run build` 和相关测试通过。
