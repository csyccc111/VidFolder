# v0.4 大目录性能基准测试指南

版本：v0.4 | 编制：DeepSeek-V4 Flash，2026-08-10 | 执行人：用户自测

## 目的

对 500、2000、5000+ 三档视频规模建立可复现的性能结论，判断是否需要针对性优化。**测试结论是优化决策的依据；未达基线才优化，达到基线则保持现状。**

### 0.2 测试数据构造

- 准备少量代表性视频（不同分辨率、横竖屏、含中文文件名、含空格文件名、含特殊字符如 `（）【】&+#` 的文件名）。
- 复制构造三个测试目录（不含子目录层级时可用脚本构造多层目录）：
  - `bench-500`：约 500 个视频，含 3-5 层子目录。
  - `bench-2000`：约 2000 个视频，含 5-8 层子目录。
  - `bench-5000`：5000+ 个视频，含 8+ 层子目录。
- 记录每个测试目录：视频总数、总大小、目录层级数、文件名是否覆盖中文/空格/特殊字符。

### 0.3 隔离测试环境（重要）

- 测试使用**独立的用户数据目录**，不得读取/清空日常缓存：
  - 打包版：先备份（或清空）原 `%APPDATA%/Vid Folder Browser`，测试完成后恢复。
  - 或启动前设置环境变量 `APPDATA` 指向临时目录再运行。
- 每个场景**至少重复 3 次**，记录 3 次结果，取**中位数**作为结论值，同时保留最大值观察抖动。

## 1. 三档 × 三态矩阵

每档（500 / 2000 / 5000+）都要测三种缓存状态：

| 状态 | 准备方法 |
|---|---|
| 冷缓存 | 清空测试用 `cache/` 与 `metadata-cache.json` 后首次扫描 |
| 热缓存 | 冷缓存扫描完成后立即再次扫描（不重启应用或重启后均可，各记一次） |
| 混合缓存 | 在热缓存基础上：①替换其中约 20% 视频文件（大小或 mtime 变化）；②删除约 5% 视频文件；③把约 2% 的缩略图 jpg 文件内容写坏（如用记事本写入 "broken" 或置零字节） |

## 2. 每轮测试步骤

1. 打开任务管理器（性能页）或 `tasklist /m` 监控进程内存；记录扫描前内存基线。
2. 选择文件夹开始扫描，秒表计时，记录：
   - **首个视频出现时间**（从点击扫描到网格出现第一张卡片）。
   - **文件发现完成时间**（状态栏"视频 N"停止增长）。
   - **元信息完成时间**（列表视图"时长/分辨率"列全部不再变化；或详情面板时长不再变化）。
   - **封面完成时间**（状态栏"封面 N/M"达到 M 且不再变化）。
   - **扫描期间 UI 可交互性**（能否滚动/搜索/切换视图；有无明显卡死窗口，记录卡死时长）。
3. 扫描完成后立即记录：峰值内存、完成时内存（任务管理器）。
4. 交互操作（网格与列表各做一遍）：
   - 搜索一个关键词 → 结果出现耗时。
   - 切换排序（如按时长降序）→ 结果刷新耗时。
   - 组合筛选（格式 + 时长 + 画面）→ 结果刷新耗时。
   - 快速滚动列表到底部 → 是否明显卡顿（记录卡顿秒数）。
5. 热缓存：直接点"刷新"再扫一遍，记录耗时（对比冷缓存）。
6. 记录失败数（状态栏"失败 N"）与失败原因分布（详情面板文案分类）。

## 4. 性能基线（判定标准）

| 编号 | 基线 | 判定 |
|---|---|---|
| B1 | 5000+ 热缓存扫描过程中窗口不长期无响应、不崩溃 | 未达 → 需优化 |
| B2 | 首批结果增量出现，不等待全部扫描后一次性展示 | 未达 → 需优化 |
| B3 | 搜索/筛选/排序操作无持续数秒冻结 | 未达 → 需优化 |
| B4 | 扫描结束后内存不持续无界增长（完成后 30 秒内存与峰值差距 ≤ 20%） | 未达 → 需优化 |

## 5. 可复核证据

- 建议录屏全程（Windows 自带 Xbox Game Bar 或其它录屏工具）。
- 或 DevTools Performance 记录（打包版需临时开 devtools，或直接测 `npm run dev` 形态）。
- 或按固定间隔（如每 5 秒）采样进程内存，形成曲线。

## 7. 注意

- 若构造测试集需要更多代表性视频，向开发说明缺失类型；**不要从网上下载来源不明的媒体**。
- 测试中途不要清空用户日常缓存；测试目录与日常目录严格分离。
- 每个场景 3 次的"第 1 次"建议视为预热，结论以中位数为准。
