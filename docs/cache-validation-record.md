# v0.4 缓存失效验证记录

版本：v0.4 | 编制：DeepSeek-V4 Flash，2026-08-10 | 执行人：用户自测

## 缓存机制说明

- 缓存 key = SHA-1(文件绝对路径 | 文件大小 | 修改时间 mtime)。
- key 相同 → 命中缓存，复用元信息与缩略图。
- 元信息存于 `metadata-cache.json`，缩略图存于 `cache/<key>.jpg`。
- 两者均为应用数据目录（`%APPDATA%/Vid Folder Browser/`）下的文件，与应用无关的用户文件不会被触碰。

## 验证场景矩阵

在**测试专用目录**（非日常目录）执行。每项记录"预期 / 实测 / 结论 / 是否修复"。

| # | 场景 | 操作步骤 | 预期行为 |
|---|---|---|---|
| S1 | 文件大小变化 | 替换某视频为同路径、不同大小的另一视频，点刷新 | 该视频重新探测元信息并重新生成封面 |
| S2 | 大小相同、mtime 变化 | 用同大小内容（或 touch 修改时间）改变某视频的修改时间，点刷新 | 该视频重新探测并重新生成封面 |
| S3 | 路径/大小/mtime 均不变但内容变化 | 原样替换视频内容但保持大小与 mtime（如修改后恢复时间戳） | **已知边界**：可能命中旧缓存不重新生成；此为当前 key 策略的限制，v0.4 接受此边界（不引入全文件哈希） |
| S4 | 源视频删除后残留 | 扫描完成后删除某视频文件，再次扫描该目录 | 该视频不再出现；其元信息记录与缩略图在扫描完成后被清理（仅限当前扫描根目录内确认失效的记录；被其它文件夹缓存引用的缩略图保留） |
| S5 | 缩略图文件缺失 | 删除 `cache/` 中某缩略图 jpg，点刷新 | 该视频封面显示"生成中"，随后自动重新生成 |
| S6 | 缩略图零字节/损坏 | 把某缩略图 jpg 内容置空或写坏（如写 "broken"），点刷新 | 该视频封面自动重新生成，应用不崩溃 |
| S7 | metadata-cache.json 损坏 | 退出应用，把 `metadata-cache.json` 内容改成乱码，重新启动并扫描 | 应用正常启动，从空缓存重新开始，原损坏文件被备份（`metadata-cache.corrupt-*.json`），不崩溃 |
| S8 | 跨文件夹共用缓存 | 先扫描 A 目录，再扫描 B 目录（A、B 互不包含） | A 的缓存记录与缩略图保留，不被 B 的扫描清理误删 |
| S9 | 重新生成封面（上下文菜单） | 对某视频右键"重新生成封面" | 仅封面重新生成；若元信息已有效则保留不被破坏；失败时元信息状态不变 |
| S10 | 损坏视频 | 把一个任意文件改后缀为 .mp4，扫描 | 该文件元信息失败、封面失败均被归类记录，应用不崩溃，其它视频正常 |
